# 通用私有文件与项目附件

## 1. 分层：文件不属于某一个业务模块

- `common_file`：通用文件元数据。记录原始名称、随机存储标识、大小、检测出的类型、SHA256、上传人、临时有效期和首次被业务接纳的时间。没有项目ID、审批实例ID或业务状态。
- `biz_project_file`：项目与文件的关联表。联合主键是 `project_id + file_id`，`removed_time` 记录从当前资料中移除的时间。同一文件可以关联多个项目。
- 项目资料版本：快照保存 `attachment_ids` 和服务端生成的文件展示信息，保留当时的附件清单。移除当前附件不会删除历史文件。

其他业务接入时，复用公共接口和公共组件；自己管理文件关联、保存事务以及下载权限。无需修改通用文件表，也不要在通用文件服务里增加 `if business_key == 'xxx'`。

## 2. 创建和修改时的调用顺序

1. 选择附件，前端调用 `POST /common/file/private/upload`，只发送文件。上传不要求先有项目ID。
2. 服务端把文件写入私有目录，创建24小时有效的临时记录，返回 `id/original_name/size_bytes/content_type`，不返回磁盘路径或公开URL。
3. 前端保存草稿或直接提交时，在原业务请求中携带 `attachment_ids`，不再次传文件。
4. 业务先校验对象权限，再在同一事务中调用 `PrivateFileService.accept(ids, existing_ids)`，维护自己的关联表及资料快照。新关联只允许使用本人上传的文件。
5. 保存或提交失败，业务关联和文件接纳一并回滚；已上传文件仍为临时文件，可在有效期内重试。

文件上传中、上传失败未处理或移除请求未完成时，项目页不允许保存/提交。上传失败可重试或移除。

前端复用位置：

- `frontend/web/src/api/module_common/private-file.ts`
- `frontend/web/src/components/forms/fa-private-file-upload/index.vue`
- `frontend/web/src/components/media/fa-private-file-list/index.vue`

公共组件不导入项目或流程页面，也不依赖流程样式。项目页传入业务下载上下文即可。

## 3. 下载必须经过鉴权

`GET /common/file/private/{id}/download`

- 临时文件：仅有效上传人可下载；废弃或过期后不可下载。
- 业务接纳后的文件：要求业务上下文，并调用业务注册的权限策略。单独知道文件ID不能下载。
- 项目注册 `register_file_access('project', authorize_file_download)`，校验项目可见范围；普通审批人可通过属于本人的待办/已办任务下载，不因此取得其他项目的权限。
- 项目下载参数为 `business_key=project`、`business_id`，可选 `revision_id/task_id`。服务端同时核对文件关联和所选资料版本，不能通过改参数越权。
- 历史资料移除过的附件，只能在包含该附件的资料版本中下载；仍遵守业务权限。
- 以附件方式下载，设置 `Cache-Control: private, no-store` 与 `X-Content-Type-Options: nosniff`，不作为网页内联预览。

私有上传沿用业务已有的创建/编辑权限，不需要再授权 `module_common:file:upload`。项目在注册时声明既有 `module_business:project:create/update` 权限；其他业务同样注册自己的既有写权限，通用服务不写死模块名。具备任一已接入业务的创建/编辑权限即可上传本人的临时文件，实际关联仍由目标业务接口校验权限。上传限制查询只要求有效登录；本人未绑定临时文件可自行废弃。前端组件由使用它的业务页面传入 `canUpload`，不再自行检查独立文件权限。原公开上传接口的权限保持原样。

## 4. 文件限制和清理

默认单文件10MB（复用 `MAX_FILE_SIZE`），每用户最多50个有效未绑定临时文件。项目额外限制每份资料最多20个附件；这是项目业务规则，不是公共文件表规则。

私有类型白名单独立使用 `PRIVATE_FILE_EXTENSIONS`，默认支持 PDF、Office文档、TXT、CSV、PNG/JPG/JPEG、ZIP。服务端检查扩展名、危险后缀、文件名路径、实际读取大小和空文件。类型检测不等于病毒扫描；当前未接入杀毒、压缩包解压检查或内容安全检测。

未保存附件24小时后失效。界面移除刚上传的临时附件，只标记废弃；物理清理由维护命令执行。已经被任何业务接纳过的文件不自动清理，即便现在没有活跃关联，避免误删历史快照附件。

在后端目录执行，默认只预览，确认后再加 `--apply`：

```sh
python -m app.scripts.private_file_cleanup --env=prod
python -m app.scripts.private_file_cleanup --env=prod --apply
```

每次最多处理500条过期临时记录和500个孤立文件；孤立文件只检查随机命名、48小时前且数据库没有记录的文件，补偿文件已写入但上传事务提交失败的情况。不跟随符号链接、不扫描子目录、不删除其他命名的文件。未配置自动清理计划；如需定时执行，单独配置并观察磁盘余量。

## 5. 本地与服务器存储

- 本地默认 `backend/private/files`，已排除 Git、Docker构建上下文与发布打包。
- 配置项 `PRIVATE_FILE_ROOT`，相对路径以 `backend` 为基准。不能指向 `static`、公开上传目录、其子目录或涵盖它们的上级目录。
- 新文件随机重命名，权限600；新建根目录权限700。不要把私有目录加到 Nginx alias 或静态文件映射中。
- 私有文件与数据库需要配套备份；数据库备份不能替代文件备份。

Docker 提供显式叠加配置 `docker/docker-compose.attachments.yaml`：容器路径 `/home/private/files`，默认宿主路径 `/home/FastapiAdmin/data/private-files`，可通过 `PRIVATE_FILE_DATA_DIR` 指定其他私有磁盘目录。

部署前由运维创建宿主目录并授予后端容器用户UID1000读写权限。不能使用777，也不要放在公开资源目录下。实际启动时需同时指定既有 Compose 文件与本次叠加文件；现有发布脚本不会自动把叠加文件传到服务器或重建服务。检查代理上传大小、磁盘容量、备份和挂载持久性后再上线。

本次仅准备本地代码、迁移和叠加配置，未连接或部署远程服务器。

## 6. 迁移与验证范围

本地已有开发服务自动热重载并执行迁移，因此保留已应用的两条新增迁移，不改写其版本历史；再用增量迁移保留旧文件ID、原始元数据和历史移除记录，将早期附件元数据搬到通用表。搬迁完整后才移除本次开发中新增的旧附件表，发生ID或存储标识冲突时直接中止，不覆盖记录。

新部署必须带齐迁移链，先备份数据库和文件，再按项目既有迁移流程升级。降级到旧的单项目存储结构时，如已有一个文件关联多个项目会拒绝降级，防止丢失关联。

自动测试使用临时 SQLite、模拟认证/Redis和临时磁盘；它验证接口、业务权限、文件操作、迁移搬迁以及组件行为，不替代生产数据库并发测试、真实浏览器登录验收或远程服务器部署验证。
