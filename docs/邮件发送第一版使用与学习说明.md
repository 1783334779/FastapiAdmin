# 邮件发送第一版：使用与学习说明

## 1. 这一版能做什么

超级管理员主动调用一个接口，向一个邮箱发送一封纯文本邮件。后端读取本地 SMTP 配置，组装邮件，等待邮件服务器接受或返回错误。

这一版不修改项目和流程业务，不新增数据库表，不新增前端页面，不安装新依赖，不自动发送邮件。未实现邮件任务队列、自动重试、模板、附件及投递回执；这些是后续扩展，不是本次使用的前提。

使用已有的配置系统、登录认证、统一响应和操作日志。测试接口仅超级管理员可调用，普通用户即使拥有通配菜单权限也不能调用。每位管理员每 60 秒最多尝试发送一次；Redis 不可用时拒绝发送，失败也保留冷却。

## 2. 前提与本地配置

已有 163 邮箱，已经开启 SMTP，并取得客户端授权码。后端和项目原有数据库、Redis 能正常运行。客户端授权码不是网页登录密码，也不是项目的登录 token。

在 `backend/env/.env.dev` 中自行新增下面的配置；如果使用其他环境，应填写对应文件。不要覆盖原有配置，也不要把真实配置放进 `.env.example`。

```dotenv
MAIL_ENABLED=False
MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_SECURITY=SSL
MAIL_USERNAME=你的邮箱@163.com
MAIL_PASSWORD='你的客户端授权码'
MAIL_FROM=你的邮箱@163.com
MAIL_FROM_NAME=项目管理系统
MAIL_TIMEOUT_SECONDS=10
```

其中：

- `MAIL_USERNAME`：用于 SMTP 认证的完整邮箱地址。
- `MAIL_PASSWORD`：客户端授权码，只在本地填写，不发到聊天、接口参数或截图中。
- `MAIL_FROM`：邮件中的发件人地址。163 建议先和 `MAIL_USERNAME` 保持一致。
- `SSL / 465`：连接建立时就加密，并校验邮件服务器证书。这一版也支持 STARTTLS，但学习 163 发信时可以跳过。
- `MAIL_TIMEOUT_SECONDS`：单次 socket 操作的超时，不是整个请求的总时长。

本地 `.env.dev` 已在仓库的忽略清单中。授权码在配置对象中使用 `SecretStr` 隐藏，且不进入 `Settings.model_dump()`；本地文件本身仍是明文，应限制访问，不要分享或提交。

检查填写完成后，将 `MAIL_ENABLED` 改为 `True`，重启后端。配置有缓存，修改环境文件不应只依赖浏览器刷新或 Python 热重载。

原有开发启动命令（在 `backend` 目录执行）：

```bash
.venv/bin/python main.py run --env=dev
```

如果已有后端在运行，请在原来的终端重启，不要再启动第二个进程争抢端口。

## 3. 手动测试操作

只有你准备好主动测试时才执行以下步骤，它会发送真实邮件：

1. 正常登录当前系统的超级管理员账号。
2. 使用已有接口调试工具，或后端 Swagger 文档，调用 `POST /api/v1/common/mail/test`。开发默认端口为 8001；实际地址以你的后端配置为准。
3. 请求头携带正常登录取得的 `Authorization: Bearer <access_token>`。这是项目登录 token，不是邮箱授权码；只在本地调试工具填写，不要发到聊天中。Swagger 若遇到项目滑块验证码，请使用正常前端登录后的 token，不要关闭认证或验证码。
4. 发送下面的 JSON，将收件人换成自己的邮箱：

```json
{
  "recipient": "你的收件邮箱@163.com",
  "subject": "项目系统邮件测试",
  "text": "这是一封手动触发的测试邮件。\n如果看到这段文字，说明本次邮件已经到达这个邮箱。"
}
```

后端内部路由是 `/common/mail/test`，沿用项目现有的 `/api/v1` 根路径。开发环境通常可从 `http://127.0.0.1:8001/api/v1/docs` 找到“邮件发送”分组。

请求不接受 SMTP 地址、账号、授权码、自定义发件人、抄送或批量收件人。这些配置不能通过接口临时改写。现有操作日志会记录测试请求，正文不要填写秘密或敏感业务资料。

### 预期结果

成功响应中的关键字段：

```json
{
  "data": {
    "message_id": "<本次邮件的唯一标识>",
    "status": "ACCEPTED"
  },
  "status_code": 200,
  "success": true
}
```

`ACCEPTED` 只说明 SMTP 服务器已接受邮件，不代表对方已经收到、进入收件箱或阅读。还需要检查收件箱、垃圾邮件和可能的退信。Message-ID 是本次邮件的标识，不是防重复发送的业务幂等键。

该接口仍然等待 SMTP 结果后返回；只是把阻塞网络操作放在线程中执行，避免直接阻塞异步事件循环。它不是“立刻返回、后台排队发送”。

### 出现异常时：先预测，再查原因

可以先想一下：如果 `MAIL_ENABLED=False`，会不会连接 SMTP？普通用户调用时，会不会消耗发信次数？预测后再看下面的表。

| 结果 | 第一排查点 |
| --- | --- |
| 401 | 是否携带了有效的项目登录 token。 |
| 403 | 当前账号是否是超级管理员，不只是拥有某个菜单或角色。 |
| 422 | 收件人格式、标题/正文是否为空或超长，是否误传了配置字段。 |
| 429 | 是否在 60 秒内重复点击；失败尝试也会进入冷却。 |
| 503：功能未开启/配置不完整 | 检查当前环境文件中的 `MAIL_*`，以及是否重启后端；此时不会连接 SMTP，也不占用冷却。 |
| 503：SMTP 认证失败 | 检查完整邮箱账号、客户端授权码、SMTP 开通状态；不要改用网页登录密码。 |
| 503：限流服务不可用 | 检查项目原有 Redis 服务；不会绕过限流继续发信。 |
| 502：发件人/收件人被拒绝 | 检查发件人是否匹配账号、收件人是否正确，以及邮箱平台的发信限制。 |
| 502：证书校验失败或其他连接问题 | 检查 SMTP 地址、端口、加密方式和网络；不要关闭证书校验。 |
| 504：超时 | 先查看收件箱，投递结果可能不确定，不要马上重复发送。 |

频率限制是防止反复点击，不是“保证只发一次”。网络断开时可能无法知道邮件是否已被接受，因此第一版不自动重试。退出 SMTP 会话时的断连不会把已经接受的邮件误报为失败。

## 4. 学习时从哪里读，到哪里停

先只看以下四个位置，不需要同时打开项目或工作流代码：

1. `backend/app/modules/common/mail/schema.py`：看 `MailSendSchema`，了解接口允许传入的三个字段，以及格式、长度和换行校验。看到 `MailSendResultSchema` 结束即可。
2. `backend/app/modules/common/mail/controller.py`：从 `require_mail_admin()` 开始，接着读 `send_test_mail_controller()`，看到返回 `SuccessResponse` 停止。职责依次是：验证超级管理员 → 校验配置 → Redis 冷却占位 → 调用发送服务 → 返回结果。现有登录实现、Redis 底层和操作日志实现先跳过。
3. `backend/app/modules/common/mail/service.py`：先读 `ensure_configured()`，再读 `send()` 到 `asyncio.to_thread(...)`。此处的新机制是：阻塞的 SMTP 网络操作交给线程，但当前请求仍等待它完成。随后进入 `_deliver()` 的 `SSL` 分支，读认证和 `send_message()`，最后看 `finally` 释放连接。`STARTTLS` 分支暂时跳过，再回来读 `send()` 中的异常分类。
4. `backend/app/config/setting.py`：只看“邮件发送（可选）”这一段。路由如何挂载，可选看 `backend/app/api/v1/routers.py` 的 `MailRouter` 和 `/common`，不作为继续条件。

## 5. 验证证据与边界

开发验证使用模拟 SMTP、模拟 Redis 和隔离的 FastAPI 测试应用，覆盖配置、参数校验、权限、冷却、TLS、邮件组装、异常转换及路由注册。没有使用真实邮箱凭据，也没有连接真实 SMTP 或发送邮件。临时新增的验证文件在完成后删除，保留项目原有测试。

本次邮件临时测试 38 项全部通过，相关代码的 Ruff 检查和格式检查通过。包含临时测试的全量运行结果为 378 项通过、2 项失败，另有 61 个子测试通过。两处失败均位于未修改的原有测试：项目序列化断言没有包含当前源码新增的 `attachment_ids`、`milestones`；迁移测试期望 15 张相关表，但当前模型为 17 张。邮件功能没有新增模型或改动这些断言。

删除临时测试后重新运行原有测试：340 项通过、同样 2 项失败、61 个子测试通过。原有测试文件无改动，也没有遗留本次临时测试文件。

因此，“代码路径已通过模拟测试”和“你的 163 邮箱已经实际投递成功”是两件事。真实投递仍需你按第 3 节主动验证。

## 6. 后续扩展（可跳过）

邮件模板、发送记录、持久化待发任务、失败重试，以及在流程产生审批待办后创建通知。正式接入审批时，应在业务事务中保存待发记录，再由后台发送，不能简单把 SMTP 调用塞进流程事务并让邮件失败回滚审批。

官方参考：[Python SMTP 客户端](https://docs.python.org/3.12/library/smtplib.html)、[asyncio.to_thread](https://docs.python.org/3.12/library/asyncio-task.html#asyncio.to_thread)。
